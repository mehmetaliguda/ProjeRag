# نظام RAG (دعم متعدد المصادر)

هذا المشروع هو نظام **توليد معزز بالاسترجاع (RAG)** يعمل بالكامل محلياً. يمكنك طرح أسئلة باللغة الطبيعية والحصول على إجابات مبنية على مصادر متنوعة بما في ذلك PDF وWord وPowerPoint والصور والملفات النصية وقواعد بيانات MSSQL.

يعمل النظام **بشكل محلي بالكامل**؛ يتم تنزيل نماذج LLM وEmbedding وOCR عبر **Ollama** و **Hugging Face**، ولا يتم إرسال أي بيانات إلى الخارج.

## نظرة عامة على البنية

يتكون المشروع من مكونين رئيسيين:

- **الواجهة الأمامية**: واجهة ويب مبنية على Next.js (React). يمكن للمستخدمين إنشاء دفاتر ملاحظات، وتحميل الملفات، والمحادثة، وتكوين اتصالات MSSQL.
- **الخادم الخلفي**: واجهة برمجة تطبيقات REST مبنية على Flask (Python). تدير محرك RAG، وفهرسة المستندات، والبحث المتجهي، والاتصال بـ MSSQL، وتوليد الردود بواسطة LLM.

داخل الخادم الخلفي:
- قاعدة بيانات **SQLite** (`app.db`) تخزن بيانات دفاتر الملاحظات والمحادثات والغرف وتكوينات MSSQL.
- قاعدة البيانات المتجهية **Chroma** تخزن التضمينات في مجلد منفصل لكل غرفة مستندات.
- **LangChain / LangGraph** تدير مسار معالجة RAG.
- **المسترد الهجين** (BM25 + البحث الدلالي) و **CrossEncoderReranker** يختاران الأجزاء الأكثر صلة.

## التقنيات والنماذج المستخدمة

| الغرض | التقنية / النموذج |
|--------------------------|-----------------------------------------------------------------------------------------------------------|
| **إطار الويب (الخادم الخلفي)** | Flask 3.0 |
| **إطار الويب (الواجهة الأمامية)** | Next.js 16 + React 19 + Tailwind CSS 4 |
| **قاعدة البيانات المتجهية** | Chroma (langchain-chroma) |
| **نموذج التضمين** | `bge-m3` (عبر OllamaEmbeddings) |
| **LLM (توليد الردود)** | `qwen2.5:7b-instruct` (عبر Ollama، يستخدم أيضاً لتحسين الاستعلامات وإعادة الترتيب) |
| **نموذج OCR** | `tiiuae/Falcon-OCR` (Hugging Face transformers، للصور وملفات PDF الممسوحة ضوئياً) |
| **معالجة PDF** | PyMuPDF (fitz) + LangChain PyMuPDFLoader؛ الرجوع إلى Falcon-OCR للصفحات الممسوحة ضوئياً |
| **قاعدة البيانات** | SQLite (Flask-SQLAlchemy) |
| **الاتصال بـ MSSQL** | `pyodbc` + `ODBC Driver 18 for SQL Server` |
| **التشفير** | Fernet (cryptography) لتشفير كلمات مرور MSSQL |
| **تحويلات الملفات** | LibreOffice (headless) لتحويل .doc/.ppt القديمة و .docx/.pptx إلى PDF |

## التثبيت

### المتطلبات الأساسية

- **Python 3.10+** (الخادم الخلفي)
- **Node.js 20+** و **pnpm** أو **npm** (الواجهة الأمامية)
- **Ollama** مثبت وقيد التشغيل ([ollama.com](https://ollama.com))
- **LibreOffice** – لتحويل بعض صيغ الملفات إلى PDF:
  - Ubuntu/Debian: `sudo apt-get install -y libreoffice`
  - Windows/macOS: [تحميل LibreOffice](https://www.libreoffice.org/download/)
- **ODBC Driver 18 for SQL Server** (إذا كنت تستخدم MSSQL):
  - تعليمات التثبيت الرسمية من Microsoft: [Linux](https://learn.microsoft.com/sql/connect/odbc/linux-mac/installing-the-microsoft-odbc-driver-for-sql-server)، [Windows](https://learn.microsoft.com/sql/connect/odbc/windows/system-requirements-installation-and-driver-files)
- **Git** (اختياري)

### إعداد الخادم الخلفي

```bash
cd backend
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### إعداد الواجهة الأمامية

من جذر المشروع:

```bash
pnpm install     # أو npm install
```

### تحميل نماذج Ollama

قبل تشغيل Ollama، قم بتحميل النماذج المطلوبة:

```bash
ollama pull bge-m3
ollama pull qwen2.5:7b-instruct
```

> **ملاحظة:** يستخدم `bge-m3` للتضمينات، ويستخدم `qwen2.5:7b-instruct` لتوليد الردود وإعادة الترتيب. قد تكون أحجام النماذج كبيرة (bge-m3 ~1.2GB، qwen2.5:7b ~4.7GB).

نموذج OCR **غير متوفر على Ollama**؛ سيتم تحميله تلقائياً من Hugging Face عند أول استخدام. للتحميل يدوياً:

```bash
python -c "from transformers import AutoModelForCausalLM; model = AutoModelForCausalLM.from_pretrained('tiiuae/Falcon-OCR', trust_remote_code=True); model.save_pretrained('./models/falcon-ocr')"
```

### متغيرات البيئة (.env)

يقرأ الخادم الخلفي الإعدادات من `backend/rag.env`. أنشئ ملف `rag.env` بالمحتوى التالي:

```ini
# إعدادات Ollama
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=qwen2.5:7b-instruct

# نموذج التضمين
EMBED_MODEL=bge-m3

# مجلد قاعدة البيانات المتجهية
RAG_ROOMS_ROOT=./rag_rooms

# مفتاح تشفير MSSQL (Fernet)
# لتوليد مفتاح جديد:
# python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
MSSQL_ENC_KEY=مفتاحك_المولد_هنا

# برنامج تشغيل ODBC لـ MSSQL (افتراضي: ODBC Driver 18 for SQL Server)
MSSQL_ODBC_DRIVER=ODBC Driver 18 for SQL Server

# نموذج OCR (اختياري)
FALCON_OCR_MODEL_ID=tiiuae/Falcon-OCR
FALCON_OCR_LOCAL_PATH=./models/falcon-ocr

# إعدادات إضافية اختيارية
APP_BASE_URL=http://127.0.0.1:5000
DATABASE_URL=sqlite:///app.db
```

**مهم:** لن يعمل الاتصال بـ MSSQL بدون `MSSQL_ENC_KEY`. إذا تركته فارغاً، سيرمي التطبيق خطأ.

## تشغيل التطبيق

### 1. تشغيل Ollama

```bash
ollama serve
```

تحقق من أنه يعمل:

```bash
curl http://localhost:11434
```

أو قم بزيارة `http://localhost:11434` في متصفحك.

### 2. تشغيل الخادم الخلفي

في نافذة طرفية جديدة:

```bash
cd backend
source venv/bin/activate   # Windows: venv\Scripts\activate
flask --app app.py run
```

يستمع الخادم الخلفي على `http://127.0.0.1:5000` افتراضياً.

### 3. تشغيل الواجهة الأمامية

في نافذة طرفية أخرى (من جذر المشروع):

```bash
npm run dev
```

أو

```bash
pnpm run dev
```

الواجهة الأمامية متاحة على `http://localhost:3000`.

## الاستخدام

### إنشاء دفاتر الملاحظات وتحميل الملفات

1. افتح `http://localhost:3000` في متصفحك.
2. انقر على زر **"New Notebook"** في أعلى اليمين وأعطه اسماً.
3. انقر على دفتر الملاحظات للدخول إلى صفحة المحادثة.
4. في اللوحة اليسرى تحت **"Sources"**، اسحب وأفلت الملفات أو انقر على منطقة **"Drop files here"** لتحديد الملفات.
5. تتم إضافة المستندات المرفوعة تلقائياً إلى قاعدة البيانات المتجهية ويتم **تحديدها** افتراضياً. يمكنك تحديد مستندات متعددة للاستعلام عنها في وقت واحد.

### طرح الأسئلة (RAG)

- اكتب سؤالك في واجهة المحادثة واضغط Enter.
- يقوم النظام بإجراء بحث متجهي، ويختار الأجزاء الأكثر صلة، ويولد رداً باستخدام **qwen2.5:7b-instruct**.
- تتضمن الردود علامات `[[c:N]]` تشير إلى المصادر؛ انقر عليها لعرض الصفحة/النص المقتبس.

### الاتصال بقاعدة بيانات MSSQL

لاتصال دفتر ملاحظات بـ MSSQL:

1. في قسم **"Data Sources"** في الصفحة الرئيسية، حدد دفتر الملاحظات الخاص بك.
2. في لوحة **MSSQL Configuration**، املأ ما يلي:
   1. **Server** – اسم الخادم أو عنوان IP
   2. **Port** – عادة 1433
   3. **Database Name** – اسم قاعدة البيانات
   4. **Username** – اسم مستخدم قاعدة البيانات
   5. **Password** – كلمة مرور قاعدة البيانات (اتركها فارغة عند التحديث للاحتفاظ بكلمة المرور الحالية)
   6. **Table Name** – الجدول المراد الاستعلام عنه
   7. **Timestamp Column** – عمود الطابع الزمني لترتيب أحدث السجلات
   8. **Text Columns** – الأعمدة التي تحتوي على بيانات نصية (مفصولة بفواصل، مثال: `message, level, source`)
3. انقر على **"Save & Test Connection"**. يختبر الخادم الخلفي الاتصال ويحفظه في حالة النجاح.
4. اذهب إلى دفتر الملاحظات وحدد **"SQL Source"** من قائمة المصادر.
5. اطرح أسئلة باللغة الطبيعية؛ يقوم النظام بتوليد ردود باستخدام كل من المستندات وبيانات MSSQL.

## صيغ الملفات المدعومة

يمكن تحميل واستخدام الصيغ التالية في RAG:

```
.pdf   .md    .txt   .docx  .pptx  .doc   .ppt
.jpg   .jpeg  .png
```

- **PDF**: يتم استخراجه مباشرة إذا كانت هناك طبقة نصية؛ ملفات PDF الممسوحة ضوئياً/الصور تستخدم Falcon-OCR كحل احتياطي.
- **الصور**: يقوم OCR للصفحة الكاملة بتحويل الصور إلى نص.
- **Word/PowerPoint**: يتم معالجة النص والصور المضمنة بشكل منفصل (تخضع الصور لـ OCR).
- **.doc/.ppt القديمة**: يتم تحويلها إلى .docx/.pptx باستخدام LibreOffice قبل المعالجة.

## استكشاف الأخطاء وإصلاحها

### خطأ اتصال Ollama

- تحقق من أن `ollama serve` قيد التشغيل.
- تأكد من أن `OLLAMA_BASE_URL` صحيح (افتراضي: `http://localhost:11434`).
- تأكد من تحميل النماذج (`ollama list` للتحقق).

### فشل تشغيل الخادم الخلفي

- تأكد من تثبيت جميع التبعيات من `requirements.txt`.
- تأكد من وجود `rag.env` في دليل `backend/`.
- تحقق من أذونات الكتابة لملف قاعدة بيانات SQLite (`app.db`).

### خطأ اتصال MSSQL

- هل `MSSQL_ENC_KEY` محددة وهي مفتاح Fernet صحيح؟
- هل تم تثبيت ODBC Driver 18؟
- هل الخادم والمنفذ واسم قاعدة البيانات واسم الجدول صحيحة؟
- يجب ألا تحتوي أسماء الجداول/الأعمدة على أحرف خاصة أو مسافات (فقط حروف وأرقام و `_`).

### خطأ LibreOffice

يتطلب تحويل الملفات أمر `soffice`. إذا لم يكن مثبتاً:

```bash
sudo apt-get install -y libreoffice
```

### OCR بطيء أو خطأ GPU

نموذج Falcon-OCR كبير وقد يكون بطيئاً على وحدة المعالجة المركزية. إذا لم تتوفر GPU، تحلى بالصبر أو فكر في استخدام نموذج OCR أخف.

## ملاحظات الأمان

- يتم تشفير كلمات مرور MSSQL باستخدام **Fernet** وتخزينها في قاعدة البيانات؛ لا تعيد API كلمة المرور بنص واضح أبداً.
- يتم التحقق من استعلامات SQL مقابل قائمة بيضاء صارمة لأسماء الجداول/الأعمدة (لمنع الحقن).
- يعمل النظام محلياً بالكامل؛ مستنداتك واستعلاماتك لا تغادر جهازك أبداً.
- بالنسبة للبيانات الحساسة، يوصى بتقييد الوصول إلى الشبكة للتطبيق.
