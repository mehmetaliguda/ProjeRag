# سیستم RAG (پشتیبانی از چندین منبع داده)

این پروژه یک سیستم **تولید افزایش‌یافته با بازیابی (RAG)** است که کاملاً به صورت محلی اجرا می‌شود. می‌توانید سوالات خود را به زبان طبیعی بپرسید و پاسخ‌هایی مبتنی بر منابع مختلف از جمله PDF، Word، PowerPoint، تصاویر، فایل‌های متنی و پایگاه‌های داده MSSQL دریافت کنید.

سیستم **کاملاً محلی** اجرا می‌شود؛ مدل‌های LLM، Embedding و OCR از طریق **Ollama** و **Hugging Face** دانلود می‌شوند و هیچ داده‌ای به بیرون ارسال نمی‌شود.

## نمای کلی از معماری

پروژه از دو جزء اصلی تشکیل شده است:

- **فرانت‌اند**: رابط وب مبتنی بر Next.js (React). کاربران دفترچه‌های یادداشت ایجاد می‌کنند، فایل آپلود می‌کنند، چت می‌کنند و اتصالات MSSQL را پیکربندی می‌کنند.
- **بک‌اند**: API REST مبتنی بر Flask (Python). موتور RAG، نمایه‌سازی اسناد، جستجوی برداری، اتصال MSSQL و تولید پاسخ توسط LLM را مدیریت می‌کند.

در داخل بک‌اند:
- پایگاه داده **SQLite** (`app.db`) اطلاعات دفترچه‌های یادداشت، مکالمات، اتاق‌ها و پیکربندی MSSQL را ذخیره می‌کند.
- پایگاه داده برداری **Chroma** جاسازی‌ها را در یک پوشه جداگانه برای هر اتاق سند ذخیره می‌کند.
- **LangChain / LangGraph** خط لوله RAG را مدیریت می‌کند.
- **بازیاب ترکیبی** (BM25 + جستجوی معنایی) و **CrossEncoderReranker** مرتبط‌ترین قطعات را انتخاب می‌کنند.

## فناوری‌ها و مدل‌های استفاده شده

| هدف | فناوری / مدل |
|--------------------------|-----------------------------------------------------------------------------------------------------------|
| **چارچوب وب (بک‌اند)** | Flask 3.0 |
| **چارچوب وب (فرانت‌اند)** | Next.js 16 + React 19 + Tailwind CSS 4 |
| **پایگاه داده برداری** | Chroma (langchain-chroma) |
| **مدل جاسازی** | `bge-m3` (از طریق OllamaEmbeddings) |
| **LLM (تولید پاسخ)** | `qwen2.5:7b-instruct` (از طریق Ollama، همچنین برای بهینه‌سازی پرس و جو و بازرتبه‌بندی استفاده می‌شود) |
| **مدل OCR** | `tiiuae/Falcon-OCR` (Hugging Face transformers، برای تصاویر و PDFهای اسکن شده) |
| **پردازش PDF** | PyMuPDF (fitz) + LangChain PyMuPDFLoader؛ بازگشت به Falcon-OCR برای صفحات اسکن شده |
| **پایگاه داده** | SQLite (Flask-SQLAlchemy) |
| **اتصال MSSQL** | `pyodbc` + `ODBC Driver 18 for SQL Server` |
| **رمزگذاری** | Fernet (cryptography) برای رمزگذاری رمزهای عبور MSSQL |
| **تبدیل فایل‌ها** | LibreOffice (headless) برای تبدیل .doc/.ppt قدیمی و .docx/.pptx به PDF |

## نصب

### پیش‌نیازها

- **Python 3.10+** (بک‌اند)
- **Node.js 20+** و **pnpm** یا **npm** (فرانت‌اند)
- **Ollama** نصب شده و در حال اجرا ([ollama.com](https://ollama.com))
- **LibreOffice** – برای تبدیل برخی فرمت‌های فایل به PDF:
  - Ubuntu/Debian: `sudo apt-get install -y libreoffice`
  - Windows/macOS: [دانلود LibreOffice](https://www.libreoffice.org/download/)
- **ODBC Driver 18 for SQL Server** (اگر از MSSQL استفاده می‌کنید):
  - دستورالعمل‌های نصب رسمی از Microsoft: [Linux](https://learn.microsoft.com/sql/connect/odbc/linux-mac/installing-the-microsoft-odbc-driver-for-sql-server)، [Windows](https://learn.microsoft.com/sql/connect/odbc/windows/system-requirements-installation-and-driver-files)
- **Git** (اختیاری)

### راه‌اندازی بک‌اند

```bash
cd backend
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### راه‌اندازی فرانت‌اند

از ریشه پروژه:

```bash
pnpm install     # یا npm install
```

### دانلود مدل‌های Ollama

قبل از راه‌اندازی Ollama، مدل‌های مورد نیاز را دانلود کنید:

```bash
ollama pull bge-m3
ollama pull qwen2.5:7b-instruct
```

> **توجه:** `bge-m3` برای جاسازی استفاده می‌شود، `qwen2.5:7b-instruct` برای تولید پاسخ و بازرتبه‌بندی استفاده می‌شود. اندازه مدل‌ها ممکن است بزرگ باشد (bge-m3 ~1.2GB، qwen2.5:7b ~4.7GB).

مدل OCR **در Ollama موجود نیست**؛ در اولین استفاده به طور خودکار از Hugging Face دانلود می‌شود. برای دانلود دستی:

```bash
python -c "from transformers import AutoModelForCausalLM; model = AutoModelForCausalLM.from_pretrained('tiiuae/Falcon-OCR', trust_remote_code=True); model.save_pretrained('./models/falcon-ocr')"
```

### متغیرهای محیطی (.env)

بک‌اند تنظیمات را از `backend/rag.env` می‌خواند. یک فایل `rag.env` با محتوای زیر ایجاد کنید:

```ini
# تنظیمات Ollama
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=qwen2.5:7b-instruct

# مدل جاسازی
EMBED_MODEL=bge-m3

# پوشه پایگاه داده برداری
RAG_ROOMS_ROOT=./rag_rooms

# کلید رمزگذاری MSSQL (Fernet)
# برای تولید کلید جدید:
# python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
MSSQL_ENC_KEY=کلید_تولید_شده_شما_اینجا

# درایور ODBC MSSQL (پیش‌فرض: ODBC Driver 18 for SQL Server)
MSSQL_ODBC_DRIVER=ODBC Driver 18 for SQL Server

# مدل OCR (اختیاری)
FALCON_OCR_MODEL_ID=tiiuae/Falcon-OCR
FALCON_OCR_LOCAL_PATH=./models/falcon-ocr

# تنظیمات اضافی اختیاری
APP_BASE_URL=http://127.0.0.1:5000
DATABASE_URL=sqlite:///app.db
```

**مهم:** اتصال MSSQL بدون `MSSQL_ENC_KEY` کار نخواهد کرد. اگر خالی گذاشته شود، برنامه خطا می‌دهد.

## اجرای برنامه

### 1. راه‌اندازی Ollama

```bash
ollama serve
```

بررسی کنید که در حال اجرا است:

```bash
curl http://localhost:11434
```

یا در مرورگر خود به `http://localhost:11434` بروید.

### 2. راه‌اندازی بک‌اند

در یک ترمینال جدید:

```bash
cd backend
source venv/bin/activate   # Windows: venv\Scripts\activate
flask --app app.py run
```

بک‌اند به طور پیش‌فرض روی `http://127.0.0.1:5000` گوش می‌دهد.

### 3. راه‌اندازی فرانت‌اند

در ترمینال دیگری (از ریشه پروژه):

```bash
npm run dev
```

یا

```bash
pnpm run dev
```

فرانت‌اند در `http://localhost:3000` در دسترس است.

## استفاده

### ایجاد دفترچه یادداشت و آپلود فایل‌ها

1. `http://localhost:3000` را در مرورگر خود باز کنید.
2. روی دکمه **"New Notebook"** در بالا سمت راست کلیک کنید و یک نام به آن بدهید.
3. روی دفترچه یادداشت کلیک کنید تا وارد صفحه چت شوید.
4. در پنل سمت چپ زیر **"Sources"**، فایل‌ها را بکشید و رها کنید یا روی منطقه **"Drop files here"** کلیک کنید تا فایل‌ها را انتخاب کنید.
5. اسناد آپلود شده به طور خودکار به پایگاه داده برداری اضافه می‌شوند و به طور پیش‌فرض **انتخاب** می‌شوند. می‌توانید چندین سند را برای پرس و جو همزمان انتخاب کنید.

### پرسیدن سوال (RAG)

- سوال خود را در رابط چت تایپ کنید و Enter را بزنید.
- سیستم جستجوی برداری را انجام می‌دهد، مرتبط‌ترین قطعات را انتخاب می‌کند و با استفاده از **qwen2.5:7b-instruct** پاسخ تولید می‌کند.
- پاسخ‌ها شامل برچسب‌های `[[c:N]]` هستند که به منابع اشاره می‌کنند؛ برای مشاهده صفحه/متن نقل قول شده روی آنها کلیک کنید.

### اتصال به پایگاه داده MSSQL

برای اتصال یک دفترچه یادداشت به MSSQL:

1. در بخش **"Data Sources"** در صفحه اصلی، دفترچه یادداشت خود را انتخاب کنید.
2. در پنل **MSSQL Configuration**، موارد زیر را پر کنید:
   1. **Server** – نام سرور یا آدرس IP
   2. **Port** – معمولاً 1433
   3. **Database Name** – نام پایگاه داده
   4. **Username** – نام کاربری پایگاه داده
   5. **Password** – رمز عبور پایگاه داده (هنگام به‌روزرسانی خالی بگذارید تا رمز عبور موجود حفظ شود)
   6. **Table Name** – جدولی که باید پرس و جو شود
   7. **Timestamp Column** – ستون زمان‌مهر برای مرتب‌سازی جدیدترین رکوردها
   8. **Text Columns** – ستون‌های حاوی داده‌های متنی (با کاما جدا شده، مثال: `message, level, source`)
3. روی **"Save & Test Connection"** کلیک کنید. بک‌اند اتصال را تست می‌کند و در صورت موفقیت ذخیره می‌کند.
4. به دفترچه یادداشت بروید و **"SQL Source"** را از لیست منابع انتخاب کنید.
5. سوالات را به زبان طبیعی بپرسید؛ سیستم با استفاده از هر دو اسناد و داده‌های MSSQL پاسخ تولید می‌کند.

## فرمت‌های فایل پشتیبانی شده

فرمت‌های زیر را می‌توان آپلود کرد و در RAG استفاده کرد:

```
.pdf   .md    .txt   .docx  .pptx  .doc   .ppt
.jpg   .jpeg  .png
```

- **PDF**: اگر لایه متنی وجود داشته باشد مستقیماً استخراج می‌شود؛ PDFهای اسکن شده/تصویری به Falcon-OCR باز می‌گردند.
- **تصاویر**: OCR تمام صفحه تصاویر را به متن تبدیل می‌کند.
- **Word/PowerPoint**: متن و تصاویر جاسازی شده به طور جداگانه پردازش می‌شوند (تصاویر OCR می‌شوند).
- **.doc/.ppt قدیمی**: قبل از پردازش با استفاده از LibreOffice به .docx/.pptx تبدیل می‌شوند.

## عیب‌یابی

### خطای اتصال Ollama

- بررسی کنید که `ollama serve` در حال اجرا است.
- مطمئن شوید که `OLLAMA_BASE_URL` صحیح است (پیش‌فرض: `http://localhost:11434`).
- مطمئن شوید که مدل‌ها دانلود شده‌اند (`ollama list` برای بررسی).

### بک‌اند راه‌اندازی نمی‌شود

- مطمئن شوید که همه وابستگی‌های `requirements.txt` نصب شده‌اند.
- مطمئن شوید که `rag.env` در دایرکتوری `backend/` وجود دارد.
- مجوزهای نوشتن برای فایل پایگاه داده SQLite (`app.db`) را بررسی کنید.

### خطای اتصال MSSQL

- آیا `MSSQL_ENC_KEY` تعریف شده و یک کلید Fernet معتبر است؟
- آیا ODBC Driver 18 نصب شده است؟
- آیا سرور، پورت، نام پایگاه داده و نام جدول صحیح هستند؟
- نام‌های جدول/ستون نباید دارای کاراکترهای خاص یا فاصله باشند (فقط حروف، اعداد و `_`).

### خطای LibreOffice

تبدیل فایل به دستور `soffice` نیاز دارد. اگر نصب نشده است:

```bash
sudo apt-get install -y libreoffice
```

### OCR کند یا خطای GPU

مدل Falcon-OCR بزرگ است و ممکن است روی CPU کند باشد. اگر GPU در دسترس نیست، صبور باشید یا از یک مدل OCR سبک‌تر استفاده کنید.

## نکات امنیتی

- رمزهای عبور MSSQL با استفاده از **Fernet** رمزگذاری شده و در پایگاه داده ذخیره می‌شوند؛ API هرگز رمز عبور را به صورت متن ساده برنمی‌گرداند.
- پرس و جوهای SQL در برابر یک لیست سفید سختگیرانه برای نام‌های جدول/ستون تأیید می‌شوند (جلوگیری از تزریق).
- سیستم کاملاً محلی اجرا می‌شود؛ اسناد و پرس و جوهای شما هرگز از دستگاه شما خارج نمی‌شوند.
- برای داده‌های حساس، توصیه می‌شود دسترسی شبکه به برنامه را محدود کنید.
